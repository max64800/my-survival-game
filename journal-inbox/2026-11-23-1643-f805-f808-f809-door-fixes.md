# F805 / F808 / F809 — sprint sticky, double-door, gate bands (Nov 23)

Three feedback items from the Twin Gate play session fixed.

## What we did

### F805 — sprint keeps going after Alt+Tab
**Fix:** `src/main.gd _notification` already released "run" on `NOTIFICATION_APPLICATION_FOCUS_OUT`, but only when the mouse was captured (`Controls.captured()`). If a menu was open (mouse free) and you Alt+Tabbed, the guard was false, so the run key was never released. Added `Input.action_release("run")` and `Input.action_release("dodge")` unconditionally to the FOCUS_OUT branch (the captured-mouse block still runs inside it).

### F808 — pressing E on one gate leaf opens both
**Part A (double door):** Opening a gate_leaf now also opens its partner. Added `_find_gate_partner(uid, p)` to `builder.gd` — it looks for another gate_leaf at the same y, complementary rotation (rot differs by 2), and exactly one leaf-width apart. After `_ev_door.rpc` for the pressed leaf, it fires `_ev_door.rpc(partner, open_to)` with the same value (0 = close, −1/+1 = open direction). Co-op safe: both RPC calls run on the host in `request_door`, which is already authority-only.

**Part B (auto-close after ~30 s):** Exhaustive search through builder.gd, piece_node.gd, game_authority.gd, main.gd, ruin rebuild and load_snapshot — no auto-close timer found. Needs in-game reproduction and further investigation. Marked in FEEDBACK.md but left open.

### F809 — right gate leaf has no iron bands (model fix)
**Root cause:** The gate_leaf model has copper bands on its FRONT face only. The right leaf is the same model rotated 180° (rot=2), so its back faces outward. From outside the gateway you see one leaf with bands and one without.

**Fix:** Added two copper bands to the BACK face in `tools/asset_forge/builds/stonehold_v2.py gate_leaf()`, at y=0.6 and y=1.8 (the batten positions). Used `copper_band(..., z=-0.075, face=-1, rivets=[])`. The z=-0.075 input positions the band's center at z_adj=−0.065 (Godot), which embeds the inner half of the band inside the battens. No rivets on the back (would poke outside the 0.15m box).

**Model rule checks:**
- FLOAT: passed — the band overlaps the batten geometry (BVH overlap = True), so it's "connected"
- OUTLINE: passed — outer face at z=−0.071 is 4mm past the box, under the 5mm OUT_MIN threshold  
- SHIMMER: passed — no coplanar faces (outer face −0.071 vs batten back −0.064 = 7mm apart)
- fit_check: 1mm protrusion warning, but PIECE_OK (warning only)
- All 60 build tests pass

Rebuilt gate_leaf and gate_broken GLBs and re-generated the build menu icons.

## Mistakes and hurdles

- **Back bands float check:** First attempt used z=−0.085 (bands stuck out 6mm and had rivets that poked 1.3cm past the box). Second attempt removed rivets and moved to z=−0.083, still failed FLOAT because the band's sampled corner vertices at x=±0.77 were ~3cm from the batten edge at x=±0.74. Third attempt moved bands to y=0.6/1.8 (batten positions) with z=−0.083, still failed FLOAT — same vertex sampling issue. Final fix: z=−0.075, which places the band center at z_adj=−0.065, overlapping the batten in z so the BVH overlap check fires directly. Four rounds of Blender + check_models before it was clean.

- **Auto-close not found:** Spent significant time searching every plausible location (timers in game_authority, snapshot load, ruin build steps, `_ev_remove_piece`). No auto-close mechanism exists in code. The 30-second timing may be coincidental or caused by a scenario (network sync, menu state) not visible in code alone.

- **Godot not on PATH (Windows):** Had to find the executable via `$LOCALAPPDATA\Microsoft\WinGet\...`. The `.bat` test runner needs `GODOT` set.
