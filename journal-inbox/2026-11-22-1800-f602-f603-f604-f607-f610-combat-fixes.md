## 2026-11-22 — F602 / F603 / F604 / F607 / F610 combat fixes

### What we did

Five combat and AI issues fixed in one session, all in `src/combat/monster.gd`, `src/combat/monster_manager.gd`, and `src/world/dungeon_build.gd`.

**F602 — Rock Beetle charge half-turn & ragdoll:**
The beetle sometimes started its charge while still mid-turn, causing it to miss. The root cause: `_start_attack` did not align the model before the wind-up began, so `charge_line` locked onto the wrong direction. Fix: at attack start, if the attack is a lunge and the monster has `straight_charge`, snap `model.rotation.y` to face the player via `mgr.player_node(target_peer)`.

The ragdoll issue: if killed during the wind-up (beetle rearing, velocity ≈ 0), `die_visual` saw `velocity.length() < 1` and the ragdoll just dropped straight down. Fix: in `die_visual`, if killed during a lunge wind-up with `straight_charge`, push the ragdoll in the model's forward direction (2.5 m/s) so it flies the right way.

**Mistake caught:** both fixes originally referenced a local variable called `target` that only exists inside `_think`'s loop — not in `die_visual` or `_start_attack`. Godot's parser caught this immediately as "Identifier 'target' not declared". Fixed by using `mgr.player_node(target_peer)` in `_start_attack` (mgr is a parameter) and using `-Basis(Vector3.UP, model.rotation.y).z` (model forward) in `die_visual`.

**F603 — Furniture destructible by monsters:**
Barrels, crates, shelves, and other dungeon props were only breakable by the player (`request_hit` checks player distance). Added `request_monster_hit(id)` to `dungeon_build.gd` — same hit/break logic but no distance check. Added `attack_smash_things(m, atk)` to `monster_manager.gd` — scans all `smash`/`rubble` props within the attack's reach and calls `request_monster_hit` for each one in front of the monster. Called from `monster.gd`'s ATTACK timer=0 block after every attack lands.

**Mistake caught:** `th.centre` from a GDScript Dictionary is untyped Variant, so `th.centre - m.global_position` couldn't be inferred as Vector3. Parser error: "Cannot infer the type of 'to' variable". Fixed by extracting `var centre: Vector3 = th.centre` first.

**F604 — Multi-target weapon hits:**
Most weapons only hit 1 enemy per swing (`max_targets_for` returned 1 for sword, dagger, hammer, etc.). Changed to return 3 for all non-sweep weapons. Sweeps (great axe, etc.) and the two-handed mace still hit everything (99).

**F607 — Combo finisher knockback:**
In `request_attack`, after `_hurt_monster`, added: if `finisher` and not a boss, call `m.knock(away_fin.normalized() * 6.0 / size)`. The `6.0 / size` scales the launch down for bigger enemies. `knock` already existed on Monster — it applies a fading push via `move_and_collide`.

**F610 — Boss/dungeon monster stuck returning home:**
The RETURN state had no stuck detection. Added `_best_dist` / `_no_progress` tracking (both variables already existed from CHASE state). If the monster doesn't get closer to home for 5 seconds AND has `dungeon_only = true`, it teleports directly to the home position. This unsticks the Pit Boss from elevator shafts and doorways without affecting surface monsters.
